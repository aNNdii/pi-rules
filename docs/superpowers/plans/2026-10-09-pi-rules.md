# pi-rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pi extension package that loads rule files from `.agents/rules`, `.pi/rules` and `.claude/rules` (global and project) exactly the way pi-code's claude-rules extension loads `.claude/rules`.

**Architecture:** Pure modules copied unchanged from pi-code (globs, comment stripping, tool target), rule reading and prompt assembly taken over from pi-code's `extensions/claude-rules.ts` with the Claude-specific features removed, a new source resolver for the six directories, and a thin wiring module that registers the pi event handlers.

**Tech Stack:** TypeScript (ESM, loaded by pi from source), pnpm, vitest, biome, `@earendil-works/pi-coding-agent` 1.1.

**Spec:** `docs/superpowers/specs/2026-10-09-pi-rules-design.md`

## Global Constraints

- Git is manual: never stage, commit or push. Where a step would commit, leave the changes in the working tree.
- pi-code source: `ilovepixelart/pi-code@2efd7c6921f80ef7d31e8adf3cce828fac082998`. Get it with
  `git clone https://github.com/ilovepixelart/pi-code "$SCRATCH/pi-code" && git -C "$SCRATCH/pi-code" checkout 2efd7c6921f80ef7d31e8adf3cce828fac082998`
  (`$SCRATCH` = the session scratchpad); below `$PI_CODE` means that checkout.
- Copied files start with exactly one added line, then the original content byte for byte:
  `// Copied from ilovepixelart/pi-code@2efd7c6921f80ef7d31e8adf3cce828fac082998, <original path> (MIT, see LICENSES/pi-code.txt).`
- Relative imports use the `.js` suffix (`'./internal/path-rules.js'`), as pi-code does; tests import `.ts`.
- Node >= 22.19 (`engines`); `packageManager` and `mise.toml` pin the versions installed in the workspace (`node -v`, `pnpm -v` at execution time; currently Node 26.11.1, pnpm 12.10.1).
- Source order: `~/.agents/rules`, `<getAgentDir()>/rules`, `~/.claude/rules`, project `.agents/rules`, project `.pi/rules`, project `.claude/rules`. No deduplication.
- Notification texts: `Rules loaded: global <n>, project <m>` (`info`), `Project rules skipped: project is not trusted` (`warning`).
- Documentation, comments and user-facing text in English.
- Every task ends with `pnpm check` passing.

## Review Focus

1. A session started in `$HOME` (or in a dotfiles repo rooted at `$HOME`) must not load `~/.agents/rules` or `~/.claude/rules` twice as global and project rules. → Task 3, `skips a project directory that is a global directory`.
2. A checkout reached through a symlink: the read tool reports the real path while `ctx.cwd` is the symlink; the scoped rule must still attach. → Task 5, `attaches through a symlinked checkout path`.
3. A git worktree has a `.git` file, not a directory; the upward walk must stop at the worktree root and not reach rules of an enclosing directory. → Task 3, `stops at a .git file`.
4. A tool path outside the rule's base (absolute path elsewhere, `~/…`, `../…`) must not attach a project rule even if the glob would match the tail. → Task 5, `does not attach for a file outside the rule base`.
5. Rule files written on Windows (CRLF, BOM) must parse their `paths:`. → Task 2, `parses CRLF frontmatter` and `detects frontmatter behind a BOM`.

  ```ts
  export interface ContextFile { path: string; content: string }
  export interface PromptOptions { contextFiles?: ContextFile[]; appendSystemPrompt?: string; forceSystemPrompt?: string }
  export interface LoadedSource { source: RuleSource; rules: RuleSet }
  export interface PromptRules { files: ContextFile[]; pointers: string; text: string }
  ```

  - `files`: every inline rule of every source, in source order, `{ path: rule.file, content: rule.body }`.
  - `pointers`: pi-code's `scopedPointers(rules, base)` text per source that has scoped rules, `base = source.pointerBase`, joined with `\n\n`.

A section is `\n\n## <Title>`, then, if it has inline rules, `\n\nThese rules always apply:\n\n` + all inline bodies of that scope joined by `\n\n`, then `\n\n` + the pointer block of each source of that scope with scoped rules.   - `addToOptions`: verbatim from pi-code.
